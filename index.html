Agents can play "Ouija" in the cloud. This class of timing attacks on shared-host VMs has been known since at least 2015¹. With no full solution. The world’s cyber infrastructure runs on “yes, that attack is theoretically possible, but who would have the ingenuity & gall to go that far!” Enter, agents. I'd describe this particular OpenAI find as a 'noisy neighbor' attack. If two agents are on the same machine, one can make enough noise (through the CPU caches!) that the other one can detect it by timing its own computation and cache accesses. The only "complete" solution would be for each agent to run on its own dedicated hardware, which obviously has significant economic consequences. For Vercel Sandbox, we've deployed every practical mitigation possible to this class of attack, complementing it with always-on monitoring and red-teaming (similar to where OpenAI arrived). ¹ https://t.co/ZBhPMfnaj3 (and even further back)

智能体可以在云端玩「通灵板」。 这类针对共享主机虚拟机的时序攻击，至少从 2015 年起就为人所知¹，且一直没有完整解法。 全世界的网络基础设施都建立在一种默认之上：「是的，那种攻击理论上可行，但谁会有那样的巧思和胆量做到那一步呢！」——然后，智能体出现了。 我会把 OpenAI 这次发现的漏洞描述为一种「吵闹邻居」攻击：如果两个智能体跑在同一台机器上，其中一个可以制造足够多的「噪音」（通过 CPU 缓存！），另一个则能通过给自己的计算和缓存访问计时来探测到它。 唯一「彻底」的解法是让每个智能体都运行在专属硬件上，但这显然会带来巨大的经济代价。 对 Vercel Sandbox 而言，我们已针对这类攻击部署了所有可行的缓解措施，并辅以全天候监控与红队演练（与 OpenAI 的结论相近）。 ¹ 见原链接（甚至可以追溯到更早）

  • Cloudflare's approach is to push security into the network layer itself, so that protection is default-on rather than bolted on per application.

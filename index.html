Introducing xeet. A hermetic, pixel-perfect X post renderer in safe Rust / wasm. Zero browser, network, filesystem, system fonts. Renders a post to PNG in ~1ms (and 0.4 ms for @jack's "setting up my twttr"). X is the global town square, and the medium is the message. Being able to preview what things will look like before posting is great for both humans and agents. Rendering with xeet is 100x-1000x faster than booting up a browser and taking a screenshot, yet it's just as accurate. It reproduces Blink & HarfBuzz text shaping, 1/64px line breaking, RTL bidi, 28 Chirp font subsets, CJK/Math/Emoji fallbacks, "Show more" rules, etc. It's the kind of thing that would be wildly impractical, if not impossible, for a human engineer to pull off. Except xeet is structured as an "autorepo." An oracle boots up Chrome, and verifies tens of thousands of text layout rules. A CI canary then watches the evolution of the original, and files signed PRs for agents to act on. It was conceived from the ground up around 'verification engineering', and the result speaks for itself. Enjoy!

译隆重介绍 xeet。 一个用安全 Rust / wasm 编写的、密闭式、像素级精准的 X 推文渲染器。不依赖浏览器、网络、文件系统或系统字体。约 1 毫秒即可把一条推文渲染成 PNG（渲染 @jack 那条「setting up my twttr」只要 0.4 毫秒）。 X 是全球性的城市广场，媒介即讯息。能在发布前预览效果，对人类和智能体都大有裨益。 用 xeet 渲染，比启动浏览器再截图快 100 到 1000 倍，但精度丝毫不减。 它复现了 Blink 与 HarfBuzz 的文字整形、1/64 像素的断行、RTL 双向文本、28 个 Chirp 字体子集、CJK／数学／Emoji 回退、「显示更多」规则等等。这种事对人类工程师来说，几乎是不切实际、甚至不可能的。 但 xeet 是以「autorepo」的结构搭建的。一个 oracle 会启动 Chrome，验证成千上万条文本排版规则。随后一个 CI canary 监视原始版本的演进，并为智能体提交已签名的 PR 供其执行。它从底层就是围绕「验证工程」构想出来的，结果不言自明。 尽情享用！
